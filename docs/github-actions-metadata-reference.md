# GitHub Actions Metadata Reference

Custom actions use `action.yml` or `action.yaml` metadata. It declares action identity, inputs, outputs, runtime behavior, and Marketplace branding.

## Basic metadata

```yaml
name: "My action"
author: "My organization"
description: "A short description of the action"
branding:
  icon: "award"
  color: "green"
```

## Inputs

Input IDs must start with a letter or underscore and contain only letters, digits, hyphens, or underscores.

```yaml
inputs:
  num-octocats:
    description: "Number of Octocats"
    required: false
    default: "1"
  octocat-eye-color:
    description: "Eye color of the Octocats"
    required: true
```

For JavaScript and Docker actions, GitHub exposes inputs as `INPUT_<UPPERCASE_VARIABLE_NAME>` environment variables. For composite actions, read inputs from the `inputs` context.

Pass required values from a workflow:

```yaml
- uses: owner/action-name@v1
  with:
    octocat-eye-color: blue
```

## Outputs

JavaScript and Docker actions declare outputs by ID:

```yaml
outputs:
  sum:
    description: "The sum of the inputs"
```

Composite actions additionally declare how the output is produced:

```yaml
outputs:
  random-number:
    description: "Random number generated by the action"
    value: ${{ steps.random-number-generator.outputs.random-id }}
```

## JavaScript actions

```yaml
runs:
  using: "node24"
  main: "main.js"
  pre: "setup.js"
  post: "cleanup.js"
```

Use `node20` or `node24`, matching the runtime declared by GitHub Actions.

Optional lifecycle scripts are supported:

- `pre` runs before `main`.
- `post` runs after `main`.
- `pre-if` and `post-if` control lifecycle conditions.

## Composite actions

```yaml
runs:
  using: "composite"
  steps:
    - name: Generate a random number
      id: random-number-generator
      run: echo "random-id=$RANDOM" >> "$GITHUB_OUTPUT"
      shell: bash
```

Composite steps may use `run`, `uses`, `shell`, `env`, `working-directory`, `with`, `if`, `continue-on-error`, `name`, and `id`.

Reference a local action with `./path/to/action`.

## Docker container actions

```yaml
runs:
  using: "docker"
  image: "Dockerfile"
  env:
    EXAMPLE: "value"
  args:
    - ${{ inputs.greeting }}
  entrypoint: "main.sh"
  pre-entrypoint: "setup.sh"
  post-entrypoint: "cleanup.sh"
```

The Dockerfile or public container image supplies the implementation. `args` values replace the container `CMD` and are passed to the entrypoint.

## Lifecycle and security notes

- Pin third-party actions to a full commit SHA for reproducibility.
- Prefer a specific major or release tag when patch updates are required.
- Use least-privilege workflow permissions.
- Keep secrets out of action metadata and repository files.
- Pin action dependencies and document required inputs.
